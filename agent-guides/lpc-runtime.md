# LPC language and runtime concepts

## LPC Language & Runtime Concepts for Agents

**When writing or reviewing LPC code, consult `docs/lpc/` first** — it is the maintained language reference, kept in sync with driver behavior: source-file/extension resolution (`docs/lpc/source-files.md`), reading compiler diagnostics (`docs/lpc/diagnostics.md`), the full preprocessor reference (`docs/lpc/preprocessor/` — define/include/conditionals/pragma), and the types/constructs pages. Testsuite conventions live in `testsuite/README.md`.

When editing compiler, VM, or package features, keep these structural mechanics in mind:

### Mudlib vs Driver Separation
* **The Driver (FluffOS)**: Written in C++, executes as the operating system, virtual machine, and compiler for LPC. It exposes built-in commands as "external functions" (efuns).
* **The Mudlib**: Written in LPC, contains the game logic, rooms, user logins, and rule definitions. It sits in a separate folder (the game tree the user picked) and is loaded by the driver. `testsuite/` is the driver’s LPC harness, not a starter mudlib.

### Source File Extensions (`.lpc` / `.c`)
* LPC source files may use either `.lpc` (preferred) or `.c` (legacy). Resolution, implemented in `load_object()` (`src/vm/internal/simulate.cc`) and pinned by `testsuite/single/tests/efuns/dual_extension.lpc`:
  - An **explicit extension is exact** — `load_object("/foo.c")` probes only `foo.c`; no `.lpc` lookup, and vice versa. On a miss the master's `compile_object()` virtual hook gets the *stripped* name; if it declines, the load returns `0`.
  - **Extension-less names prefer `.lpc`, fall back to `.c`.**
  - **Object identity is extension-blind**: object names carry no extension (`filename_to_obname()` and `otable.cc basename()` strip either spelling), so any spelling of a loaded object's name finds it — the registry is consulted before the filesystem. `prog->filename` keeps the real extension of the compiled file.
* Do **not** append `".c"` to names before loading (the old pattern); pass names through and let `load_object()` resolve. Suffix handling in `save_object`/`restore_object`, `replace_program()`, `function_exists()`, and `children()` must treat both spellings equivalently.

### Pass-by-Reference (`ref` / `&`) and String-Char Lvalues
* The `ref` keyword — and its sugar spelling `&` (both alternatives of the one `ref` nonterminal in `grammar.y`) — appears in exactly three positions: parameter declarations (`int ref x` / `int & x`, via `arg_type`), call-site arguments (`f(ref x)` / `f(& x)`, via `expr: ref lvalue`, rejected outside an argument list by `rule_expr_ref`), and `foreach` loop variables. There is no ambiguity with binary `&`: ref is always prefix, bitwise AND always infix.
* **Index lvalues are per-instance (issue #1358).** `T_LVALUE` is only a pointer to a real slot (local, global, array item, mapping value) -- or, after `F_REF` / nested `F_REF_LVALUE`, to `ref_t::index_sv` which may itself be an index lvalue. `s[i]` and `b[i]` sit on the stack as `T_LVALUE_CODEPOINT` / `T_LVALUE_BYTE` with their own heap box (or the byte pointer in the svalue). `x[a..b]` is `T_LVALUE_RANGE`; `ref x[a..b]` is a compile error. Do not reintroduce file-scope sentinels (`global_lvalue_*`). Arm through `arm_codepoint_lvalue()` / `arm_byte_lvalue()`; consume through `PoppedLvalue` (not a bare `*sp--`) so `error()` cannot leak the box. `free_svalue` must release `T_LVALUE_CODEPOINT` / `T_LVALUE_RANGE` in non-DEBUG builds too (`free_svalue_maybe_refed`). `F_MAKE_REF` of `s[i]` / `b[i]` moves the box into `ref_t::index_sv` and keeps the container alive in `ref_t::sv` -- do not stuff both into `sv`. `F_REF` of a string-char ref reads the box, not a snapshot on the `ref_t`; nested `inner(ref c)` after `outer(ref s[0])` only has `T_LVALUE` on the stack. Writes re-check bounds (`0` / `-2` from `u8_egc_index_as_single_codepoint`) so a truncated owner cannot size a replacement one byte short. Rebuild the box's `EGCSmartIterator` on each write -- do not `reset()`, whose ASCII subrange shortcut is wrong after an in-place same-length range splice.
  - **Plain `x = y` on a local, global, or functional `$n` is a specialized store**, emitted in `i_generate_node()` (not the optional optimizer): `F_ASSIGN_LOCAL` / `F_VOID_ASSIGN_LOCAL` / `F_ASSIGN_GLOBAL` / `F_VOID_ASSIGN_GLOBAL`. That includes `#pragma no_optimize` and `(: g = 1 :)`. `F_ASSIGN` remains for index, member, ref, and compound/`++` dests -- those still push a typed index lvalue or a `T_LVALUE`. The index-kind switch belongs on those dests; do not put it back on a plain slot store.
  - **Every operator that consumes `T_LVALUE_BYTE` must also handle `T_LVALUE_CODEPOINT`** or `s[i] <op>= x` throws "Bad Argument". `++`/`--`/`=` are handled in their opcodes; `+=`/`-=` go through `codepoint_lvalue_add(lval, delta)`. Writes rebuild the owner string (strings are immutable UTF-8; see `assign_lvalue_codepoint`).
  - **`s[i]` and foreach ref loop chars share ONE arming path** (`arm_codepoint_lvalue`): out-of-bounds / multi-codepoint EGC error cleanly. An EGC indexes as its FIRST codepoint when it fits in 4 bytes; wider EGCs are not char-lvalue-able -- pinned by `tests/operators/ref.lpc`.
  - **Writes through a `foreach` ref loop variable over a STRING do not propagate** to the iterated variable (the loop iterates a by-value stack copy) — pinned by `tests/operators/foreach.lpc`. Arrays and mapping values DO mutate in place.
  - Two live `s[i]` / `s[j]` lvalues must not alias (chained `s[0] = s[1] = 'x'` writes both) -- pinned by `tests/operators/index_lvalue_alias.lpc`.
  - **Buffer bytes**: every consumer reads `lval->u.lvalue_byte` / `lval->subtype`. Buffers iterate in `foreach` like arrays; a ref loop variable carries its OWN byte lvalue in `ref->sv`. Byte writes range-check 0..255. Strings and arrays of ints 0..255 PROMOTE to buffers (`do_promotions` / `svalue_to_buffer_bytes`). Pinned by `tests/operators/buffer_bytes.lpc`. A foreach ref loop variable's stale `T_REF` is released on loop re-entry.

### Simulated Efunctions (Simul_efuns)
* If an object makes a global function call (e.g. `foo()`) that is not declared inside the object and is not a built-in driver efun, the compiler resolves it as a simulated efun call.
* Simulated efuns are written in LPC and defined in a single file loaded at boot.
* Overriding built-in efuns is allowed in LPC by creating a simul_efun with the same name. To bypass a simul_efun override and invoke the driver efun directly, use the `efun::` prefix (e.g. `efun::move_object()`).
* **When you teach the compiler about a function flag, there are FOUR call-typing sites, not one.** `async` needed all of: the plain local/global call and the defined-name call (both `FUNCTION_FLAGS(f)` in `grammar_rules_exprs.cc`), the `base::fn()` qualified call (`find_matching_function()` in compiler.cc — it has `flags` in hand and used to ignore them), and the simul_efun call (below). Each was found only by testing the call route directly; a fix to one is not visible from the others.
* **`SIMUL(n)` gives you a `function_t*` — which does NOT carry the `FUNC_*` flags.** Flags live in `program_t::function_flags`, so anything about a simul_efun that keys on a flag (async, varargs, ...) has to be read the way `call_direct()` reads it when dispatching: `simul_efun_ob->prog->function_flags[simuls[n].index]`, following `FUNC_ALIAS`. Missing this types an `async` simul_efun's call site as its declared return type while the runtime hands back a promise, so `int x = some_async_simul();` compiles clean — see `simul_efun_call_type()` (compiler.cc) and `tests/efuns/async_simul_efun.lpc`. The lesson generalizes: when you teach one call path about a function flag, the simul_efun path reads its flags from a different place than every other path.

### Compile-Time Types and `promise<T>` (issue #1319)

* **The compile-time type word is `lpc_type_t` (32-bit, svalue.h)** — a different namespace from the runtime `T_*` tags in `svalue_t::type`. It carries a base `TYPE_*` (or a class index under `TYPE_MOD_CLASS`), plus `TYPE_MOD_*` / `DECL_*` / `LOCAL_MOD_*`. It was widened from `unsigned short` for `promise<T>`; the storage sites are `function_t::type`, `variable_t::type`, `class_member_entry_t::type`, `parse_node_t::type`, `keyword_t::ret_type`, `program_t::variable_types`/`::argument_types`, `type_of_locals`, and the `A_VAR_TYPE`/`A_ARGUMENT_TYPES` strides. `program_t::type_start` stays 16-bit on purpose: it indexes `argument_types` by ELEMENT, and widening the elements did not change their count.
* **The parser parks declaration modifiers in the HIGH half of the same word** (`rule_type()`'s `modifiers << 16`) until it knows whether a declaration is a function or a variable, then merges them down. That merge used bare `>> 16` / `& 0xffff`, which silently eats anything living above bit 15 — use `PACK_TYPE_MODS` / `PACKED_TYPE_MODS` / `PACKED_TYPE_BASIC` over `BASIC_TYPE_MASK` instead. Modifiers occupy bits 21–30 once shifted and bits 16–17 are already taken (`TYPE_MOD_PROMISE` = 0x10000, `TYPE_MOD_PROMISE_VALUE_ARRAY` = 0x20000, both inside `BASIC_TYPE_MASK`), so bits 18–20 are the only free space left for new type bits.
* **`promise<T>` encoding**: `TYPE_MOD_PROMISE` marks the word a promise and the rest describes the PAYLOAD. `TYPE_MOD_ARRAY` keeps its ordinary meaning ("this declaration is an array"), so `promise<int> *` (array of promises) needs no special case in the array rules; the payload's own array-ness is `TYPE_MOD_PROMISE_VALUE_ARRAY`, and the two compose. `promise_of_type()` / `promise_payload_type()` convert between a declared return type and its call-site/`await` type. There is exactly ONE promise bit, so a promise of a promise is unrepresentable by construction (matching the runtime, where resolving with a promise adopts it) — which is also what bounds `get_type_name()`'s recursion at one level.
* **Add `TYPE_MOD_PROMISE` wherever `TYPE_MOD_CLASS` appears in a mask** (`IS_CLASS`, `COMP_TYPE`, `IS_TYPE`): a `promise<class foo>` carries `TYPE_MOD_CLASS` for its payload and is not itself a class.
* **A class type word's index occupies bits 0–6, which overlap `FUNC_VARARGS` (0x20) and `FUNC_ASYNC` (0x40).** Never hand a class-typed word to a modifier printer/parser as if those were flags — class index ≥ 32 rendered as `varargs class Foo` and ≥ 64 as `async class Foo` until `get_type_name()` was taught to pass only `DECL_MODS` for class types. Classes are capped at 127, so both ranges are reachable.
* **A promise value carries its declared payload at runtime in `svalue_t::subtype`** (unused for `T_PROMISE` otherwise), as the payload's `T_*` mask via `convert_type()` — the driver's one compile-time-to-runtime mapping. Deliberately the runtime mask, not a compile-time word: a class index is program-local and a class value is a bare `array_t` with no identity, so `T_CLASS` is all the runtime can honestly say. It travels with the value for free because `assign_svalue_no_free()` copies the whole struct. It is a DECLARATION, not a measurement — an `async int f()` returning a `mixed` that holds a string still yields a promise tagged `int`.

### Applies (Driver-to-LPC Callbacks)
* "Applies" are standard callbacks that the driver VM invokes on LPC objects during specific runtime events (e.g., `create` during cloning, `init` when entering a room, `clean_up` during sweep collections).
* Applies are mapped using the `applies_table.autogen.cc` lookup tables.
* **Compile-time master applies** `inherit_program(from, path, priv)` and `include_file(compiled, from, path)` are consulted for every inherit statement / #include directive: string return redirects the path, array-of-strings return supplies the source text itself, any other return denies. They run MID-COMPILE (same precedent as `valid_override`/`get_include_path`): implementations must never trigger another compile. Reference pages in docs/apply/master/; the dependency graph they expose powers the hot-reload daemon (`testsuite/single/hot_reload.lpc`).

### Hot Reload (`recompile_object()`)
* `recompile_object(master_copy)` recompiles the source and swaps the program into the live master copy and every clone -- no destruct, identity preserved, variables carried by name (private included; new program's `__INIT` runs first, then surviving names get old values). Works for the master object, the simul_efun object (their cached dispatch tables `master_applies`/`simuls` are rebuilt against the new program BEFORE its `__INIT` runs; simul indices are name-stable by design) and virtual objects (the backing program is what recompiles).
* Invariants when touching this machinery: refuse while any live frame executes the old program (bytecode/variable indices are layout-relative); void pending `replace_program()` entries at each target's swap point (`cancel_pending_replace_program` -- entries are computed against the program being replaced and old code can register one mid-update); function pointers that depend on the owner's layout (`FP_LOCAL`, `FP_FUNCTIONAL`) carry an `owner_gen` snapshot of `ob->prog_generation` and error cleanly when stale; `FP_LOCAL` funptrs store their creation program and account `func_ref` against IT (creation/destruction must stay symmetric -- decrementing `owner->prog` corrupts counts after a swap).
